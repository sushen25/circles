# ADR 0002: Style with React Native `StyleSheet` and a tokens package generated from the design source

_Status: accepted · Date: 6 September 2026_

## Context
The design manifesto fixes a small token set (colour, two typefaces, spacing, radii, one shadow) and `docs/design/gen.py` encodes the same values for every artboard. A utility-CSS framework (NativeWind/Tailwind) would introduce a second token vocabulary and web-specific quirks in a universal app.

## Decision
`packages/tokens` is generated by `scripts/gen-tokens.ts` from the values in `docs/design/gen.py` (colour, type ramp, spacing, radii, shadow). Components in `apps/app/src/components` use `StyleSheet.create` with those tokens. No Tailwind, NativeWind or CSS-in-JS runtime.

## Alternatives considered
- **NativeWind** — faster iteration for people who know Tailwind, but duplicate tokens, a Babel/Metro plugin, and inconsistent web output.
- **Hand-written token constants** — drift from the canvas within weeks.

## Consequences
- Changing a token means changing `gen.py`, regenerating the canvas and the tokens package in one PR; the canvas and the app cannot disagree.
- Components are the only place styles are composed; screens compose components.
